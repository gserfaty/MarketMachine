# Design: Open House
**Date:** 2026-10-13 · **Status:** LOCKED — user-confirmed 2026-10-13 (chose "Open House" over "Yard Sign" and "Quiet Listing")
**Archetype:** clean consumer real estate · **Register:** calm structure · expressive at: the page headline answer (modest)
**Grounding:** Redfin's airy white listing surfaces + a newspaper real-estate section's serif headline sentence
**DNA:** clean-consumer base + type voice borrowed from editorial · **Dominant axis:** type voice
**Composition:** airy single column under the headline (pinned density; dealer not run)
**Pins:** hue = red · density = airy · register = clean consumer · red never means "down" (negative = slate blue, positive = green, always with ▲/▼ + sign) · light scheme only

## Direction
A white, spacious consumer app. Each page opens with one plain-language answer sentence set in a serif, and the data sits below it in a sober sans. Red is the brand and the action color. It is never a data direction.

## Signature move
**Roofline.** A 40×4px `--accent-solid` chevron rule (a shallow roof peak, 6px rise) sits 12px above every page's headline-answer sentence. It appears once per page and nowhere else.

## Expressive moments
- Headline answer: Newsreader at `--text-3xl` under the Roofline. Everything else holds the calm structure register.

## Type
- Display: **Newsreader** (Google Fonts, opsz 6..72, weights 500/600) — fallback `Georgia, "Times New Roman", serif`. Used for the headline-answer sentence and page titles only.
- Body/UI: **Public Sans** (Google Fonts, 400/600) — fallback `system-ui, -apple-system, "Segoe UI", sans-serif`. KPI figures and tables use `font-variant-numeric: tabular-nums`.
- Load: `@import url("https://fonts.googleapis.com/css2?family=Newsreader:opsz,wght@6..72,500;6..72,600&family=Public+Sans:wght@400;600&display=swap");`
- Scale: 1.25 (major third) from 16px:
```css
:root {
  --font-display: "Newsreader", Georgia, "Times New Roman", serif;
  --font-body: "Public Sans", system-ui, -apple-system, "Segoe UI", sans-serif;
  --text-xs: 0.75rem;   /* 12px captions, source notes */
  --text-sm: 0.875rem;  /* 14px labels, table cells, disclaimers */
  --text-base: 1rem;    /* 16px body */
  --text-lg: 1.25rem;   /* 20px subheads */
  --text-xl: 1.5rem;    /* 24px section titles */
  --text-2xl: 1.875rem; /* 30px KPI values */
  --text-3xl: 2.25rem;  /* 36px headline answer */
  --text-4xl: 3rem;     /* 48px rare hero figure */
  --leading-body: 1.55;
  --leading-display: 1.2;
}
```
- Weights: 400 / 600 (body), 500 / 600 (display). Do not use faux bold; load only these weights.

**Usage rules**
- Red (`--accent-*`) is used for the Roofline, primary buttons, links (`--accent-text`), the active nav item (`--accent-bg-subtle`), and the focus ring. It is never used for a number, a delta, a chart series, or "down".
- Deltas: `--positive` with "▲ +1.2%" and `--negative` with "▼ −2.1%". The arrow and sign are always present.
- Errors look different from the brand by form: an `--error-bg` container + a 4px `--error-text` left border + a ✕ icon + the words "Error:" or "Couldn't …". Brand red never appears in that container form. "Data source down" states use warning (amber), not error.

## Space, shape, depth
- Spacing (4px base): `--space-1` 4 · `--space-2` 8 · `--space-3` 12 · `--space-4` 16 · `--space-6` 24 · `--space-8` 32 · `--space-12` 48 · `--space-16` 64 (px). Airy defaults: 48px between page sections, 24px card padding, 16px between KPI cards, content max-width ~1120px.
- Radius: `--radius-sm` 6px (buttons, inputs) · `--radius-md` 10px (cards, callouts) · `--radius-pill` 999px (chips, nav item).
- Borders: 1px `--border-subtle` hairlines for dividers and cards. Controls use `--control-border`.
- Shadow (one level, hue-shifted, never pure black): `--shadow-card: 0 1px 2px rgb(49 45 44 / 0.06), 0 6px 16px rgb(49 45 44 / 0.06);` Cards use either a hairline or the shadow, never both stacked.
- Motion: state changes only, 150ms ease-out. Nothing animates under `prefers-reduced-motion: reduce`.

## Never
- Red for a negative value, a price drop, a down arrow, or any chart series.
- Color as the only signal for direction or status (▲/▼, the sign, and an icon or word are always present).
- A cream or beige background tint (it drifts into the serif + cream + terracotta AI-tell cluster). Stay true white.
- Inter, Roboto, or Open Sans, a third font family, or faux bold/italic.
- Newsreader at body sizes (below 20px). The serif is for headline sentences and titles only.
- A second accent hue, or raw hex values outside these tokens in app CSS.
- Nested cards, or uniform icon-heading-paragraph card grids.
- Dense analyst layouts: more than 4 KPIs in a row, or tables before the answer.

## Open questions
- Dark scheme: out of scope (red and white pin). Phase 3 sets the Streamlit base theme to light.

### Component specs
Each lists structure, tokens, states. Interactive elements cite non-text contrast (WCAG 1.4.11, 3:1) and visible focus (WCAG 2.4.7); ratios are measured from the locked tokens.

**1. Brand header** (sidebar top; organism). `.mm-brand` link to Market overview. Wordmark "michiganmen" in `--c-brand-font` at `--c-brand-size`, weight 600, `--text`; one caption line below (`--text-xs`, `--text-secondary`). Padding `--c-sidebar-pad`. No Roofline here (Roofline appears once, on the headline). States: hover underlines the wordmark; focus uses the shared ring. Citation: Jakob's law (2000): brand top-left links home.

**2. Headline-answer block** (organism, first element under the page title). `.mm-answer`:
- Roofline: `::before`, 40 by 10px box filled `--c-roofline-color`, clipped to a 4px chevron band (peak 6px above the ends): `clip-path: polygon(0 100%, 50% 0, 100% 100%, 100% 140%, 50% 40%, 0 140%)`. - Contrast: `--text` on `--background` 13.30:1; `--text-secondary` 5.89:1; Roofline fill vs `--background` 4.77:1.

**3. KPI card row** (molecule of atoms). `st.columns(n)` with n <= 4, each `st.metric(..., border=True)` (Gestalt proximity and common region; Cowan ~4). Never `"normal"` or `"inverse"`. Missing value shows "n/a" in `--text-secondary`. Cards are not interactive, so they have no hover or focus state. A caption under the card (for example the Case-Shiller note) is `--text-xs`, `--text-secondary`.

**9. Focus states** (cross-cutting). One catch-all rule covers every focusable element: `[data-testid="stAppViewContainer"] :focus-visible` (this includes the sidebar, which is inside it) gets the ring below, so new widgets are covered by default. Named as covered: slider thumb, checkbox, radio, toggle (renders as a `stCheckbox`), multiselect, text and number inputs, selectbox, buttons, nav links, tabs, expander headers. Specific hooks stay only where Streamlit suppresses or overrides its outline (buttons, selectbox wrapper, input wrapper, slider thumb). Every focusable element shows `outline: var(--c-focus-outline); outline-offset: var(--c-focus-offset);` on `:focus-visible` (keyboard only; mouse clicks show no ring). Specific hooks: `[data-testid^="stBaseButton-"]`, `[data-testid="stSlider"] div:has(> input[type="range"]:focus-visible)` (the visible thumb; the real control is a visually hidden range input), `[data-testid="stSelectbox"] :focus-visible`, `[data-testid="stMultiSelect"] :focus-visible`, and `input`. `stSlider`, `stCheckbox`, `stRadio` and `stMultiSelect` were found in the 1.64.0 bundle. In 1.64.0 the slider, selectbox and multiselect are built on react-aria, not BaseWeb (no `data-baseweb` attributes exist in the bundle), and the slider thumb has no `role="slider"` hook; the `:has()` thumb rule must be confirmed in the build screenshot, and the catch-all rule is the fallback. The 2px offset leaves a white gap, so the ring stays visible on top of a filled primary button. Contrast of `--focus-ring`: vs `--background` 4.77:1, vs `--surface` 4.61:1, vs `--accent-bg-subtle` (active nav) 4.26:1, vs `--surface-hover` 4.28:1; all pass 3:1 (WCAG 1.4.11) and the ring is 2px thick (WCAG 2.4.13 target). Nothing may clip it (WCAG 2.4.11): sidebar content keeps `--space-2` inner padding so the ring is not cut by the scroll container. Motion: under `prefers-reduced-motion: reduce` all `--c-motion` transitions are removed.
